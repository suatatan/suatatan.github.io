      02 / CONNECT

      Use your local network

      Only private or link-local addresses and local device names are accepted. There is no internet relay or public-address fallback.

      03 / TRANSFER

      Download from the sender

      Encrypted WebRTC carries the files between the two browsers. Choose “End session” at any time to stop sharing.

      Network requirements & browser limits

      Connect both devices to the same Wi-Fi or wired LAN. Guest Wi-Fi, access-point isolation, firewalls, or denied Local Network permission can prevent connections. Allow Local Network access if your browser asks. VPNs and routed private networks may also connect: a browser cannot prove that two devices are on the same physical Wi-Fi. This is a local-address restriction, not a network security boundary.

      Use a current desktop browser for best results. Where supported, files stream straight to the destination you choose. Other browsers buffer downloads in memory, limited to 200 MiB per file. Mobile browsers may pause a background tab; keep both screens awake. An interrupted transfer must be restarted. One receiver can connect per session; start a new session for another receiver.

      The public website needs internet to load. Once both pages and their connection codes have been exchanged, no internet service is used for the file transfer. The website host receives normal page requests, but the application sends it no filenames, connection codes, or file contents. Connection details are carried in the link fragment and removed from the address bar when opened.
